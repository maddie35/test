Sample 01 · product & API reference

Integrate the checkout in an afternoon

The existing guide explained the payment product beautifully. It did not explain what a developer had to do on Tuesday, in which order, or how to tell it had worked — so every integration ended in a support ticket. I rewrote it as one task with three steps and a checkpoint the reader can verify alone.

No screenshots — the UI shipped weekly

What I changed

I ran the integration myself with a sandbox key and wrote down every place I stalled. All three were ordering problems, not explanation problems: the script had to load before the bundle, the amount had to be in cents, and confirmation had to happen server-side. The concepts moved to one short page nobody has to read to succeed.

Excerpt — the rewritten topic

Add the payment method to your checkout

Before you start you need a sandbox key and a checkout page you can deploy. The whole task takes about forty minutes; step 3 is the only one that needs a back-end change.

  1. 01Load the script on your checkout page.Place it before your own bundle so the button can register itself.<script src="https://cdn.example.com/v2/checkout.js"></script>
  2. 02Render the button where the total appears.Pass the amount in cents. If the total can change without a page load, call refresh() after each change.
  3. 03Confirm the charge from your server.The browser never confirms a payment. Send the token to your back end, confirm it there, then show your own success page.
Check A test order appears in the sandbox dashboard within ten seconds. If it doesn't, the token was confirmed in the browser — see step 3.

Result

Eleven pages became four. Support stopped answering the same three questions, and the field team started sending the page instead of explaining it.

What I'd do next

Instrument the checkpoint. If readers leave at step 3, that's a product problem the documentation is quietly absorbing.
